# Homebrew and release maintenance

This repository doubles as a Homebrew tap. `Casks/hyperoptimizer.rb` installs
prebuilt, SHA-256-verified release archives on macOS and Linux (Intel/AMD64 and
ARM64). It installs `hpo`, `hyperoptimizer`, and Bash, Zsh, and Fish completions
for `hpo`. Users do not need Go or a local build toolchain.

```sh
brew tap hyperoptimizer/cli https://github.com/hyperoptimizer/cli.git
brew trust --cask hyperoptimizer/cli/hyperoptimizer
brew install hyperoptimizer
```

The explicit URL is necessary because this repository is named `cli`, rather
than `homebrew-cli`. After that one-time setup, installation, upgrades, and
uninstallation work by name. Use `brew install --cask hyperoptimizer/cli/hyperoptimizer`
if another tap introduces a conflicting name. The initial cask uses the existing
published v0.1.0 binaries; future updates are generated by GoReleaser.
Current Homebrew requires explicitly trusting this cask's installation hook;
the command above trusts this cask only.

This is a third-party tap, rather than a package in Homebrew's default repositories.
GoReleaser's current [Homebrew integration](https://goreleaser.com/customization/homebrew_casks/)
uses casks for prebuilt binaries; its older `brews` configuration is deprecated.
Current Homebrew is required, including support for casks on Linux.

## Build and review a release

Install the exact Go version in `go.mod`, Python 3.10+, and the GoReleaser version
in `.goreleaser-version`. `.goreleaser.yaml` defines all six targets, both command
names, archive formats, Debian/RPM packages, and Homebrew metadata.

1. Tag a clean commit as `vX.Y.Z` and push the tag. The release workflow verifies
   modules and generated code, runs tests and vet, then calls `sh package.sh X.Y.Z`.
2. The helper runs GoReleaser without publishing and stages public assets under
   `dist/release/`. It retains the dependency inventory and extends the checksum
   manifest to include it and the generated cask.
3. The workflow repeats the build after clearing the Go cache and compares the
   manifests. It attests every staged file with GitHub build provenance, then
   creates a **draft** GitHub release. No tap update occurs at this point.
4. Review the release notes, assets, checksums, and attestations, then publish
   the draft manually. Prerelease tags are marked as prereleases and do not
   update the stable Homebrew cask.
5. The `Update Homebrew` workflow downloads the published cask and checksum
   manifest, verifies both attestations and the cask checksum, and opens a PR
   updating `Casks/hyperoptimizer.rb`. Review and merge it to make the update
   available through `brew update` and `brew upgrade hyperoptimizer`.

GoReleaser generates the cask with `skip_upload: true`; publishing it before the
release review would point users at inaccessible draft assets. The update PR
uses the current repository's `GITHUB_TOKEN`, with no separate tap or cross-repo
secret. Enable **Settings → Actions → General → Allow GitHub Actions to create
and approve pull requests** for this repository. GitHub does not automatically
run PR workflows for a PR created by `GITHUB_TOKEN`; run CI manually on the
`codex/homebrew-vX.Y.Z` branch before merging, or use the manual update below.
The workflow can be retried with a published tag through `workflow_dispatch`;
it refuses to replace the cask with an older stable release.

For a manual update, download the generated `hyperoptimizer.rb` and
`checksums.txt` from the published release, verify them as in [VERIFYING.md](VERIFYING.md),
then copy the cask to `Casks/hyperoptimizer.rb` in an ordinary reviewed PR.

## Local validation

```sh
goreleaser check
sh package.sh --snapshot
python3 scripts/check-packages.py
```

Snapshots do not publish anything. Their cask URLs are development placeholders,
so do not merge a snapshot cask into the tap. To exercise the checked-in cask:

```sh
brew tap hyperoptimizer/cli https://github.com/hyperoptimizer/cli.git
cp Casks/hyperoptimizer.rb "$(brew --repository hyperoptimizer/cli)/Casks/hyperoptimizer.rb"
brew style hyperoptimizer/cli/hyperoptimizer
brew trust --cask hyperoptimizer/cli/hyperoptimizer
brew install --cask hyperoptimizer/cli/hyperoptimizer
hpo version
hyperoptimizer version
```

Use `brew reinstall --cask` if already installed. CI checks installation on macOS
and Linux, and checks the contents of freshly generated archives and packages.

macOS binaries are not currently Developer ID signed and notarized. On macOS,
the cask's pre-install hook removes `com.apple.quarantine` from exactly the two
staged files, `hpo` and `hyperoptimizer`, before generating completions. It does
not clear quarantine from the staging directory or change system-wide Gatekeeper
settings. Linux does not run this hook. Homebrew still verifies the archive's
SHA-256, and release provenance and draft review remain required.
This scoped workaround can be replaced with Apple signing and notarization later.

## Other package managers

The release includes `.deb` and `.rpm` packages for Linux AMD64 and ARM64. Both
install `/usr/bin/hpo` and a `/usr/bin/hyperoptimizer` symlink. These are local
package downloads, not hosted APT or YUM repositories.

GoReleaser also supports [Scoop](https://goreleaser.com/customization/scoop/),
[Winget](https://goreleaser.com/customization/winget/),
[AUR](https://goreleaser.com/customization/aur/), and
[container images](https://goreleaser.com/customization/dockers_v2/).
Those publishers are not enabled here: each needs its own destination and
review/publishing policy. A container distribution would also need a deliberate
approach to Docker Buildx access and the CLI's operating-system credential store.
